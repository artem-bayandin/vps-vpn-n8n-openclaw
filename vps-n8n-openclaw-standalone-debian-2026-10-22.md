# VPS Setup Guide (Debian 13): n8n + OpenClaw on a standalone VPS

Full setup of a **new, empty** Debian 13 (trixie) x86-64 VPS (2 GB RAM / 20 GB SSD) that runs
**n8n** and **OpenClaw** behind Cloudflare. It follows the conventions of
`vps-vpn-web-debian-2026-10-21.md` (the **VPN guide**) and reuses a few artifacts from that server
(origin certificate, AOP CA, age key, rclone remote). Nothing on the VPN server changes.

**Decisions locked in:**
- Login: **always `root` with its password** over SSH on port **2222**, same as the VPN server.
  The password must be **random, unique and ≥16 characters**, generated by a password manager.
  fail2ban and the non-standard port are the brute-force mitigations. No `sudo`, no SSH keys.
- No Xray on this server. **Nginx owns 443** directly, so Cloudflare needs no Origin Rule here.
- **No Docker.** Node.js 24 LTS from NodeSource; n8n and OpenClaw are installed with `npm` and run as
  **native systemd services**, each under **its own unprivileged user**, with a **memory cap** and a
  **strict systemd sandbox** (read-only system, write access only to its own data directory).
  Both listen on `127.0.0.1` only. This saves ~100 MB RAM and ~1.5–2 GB disk versus Docker.
- n8n uses **SQLite**, with execution history pruned after 7 days.
- Hostnames: **`n8n.<yourdomain.com>`** and **`ctrl.<yourdomain.com>`** (OpenClaw), subdomains of the
  domain you already have on Cloudflare. The website stays on the VPN server.
- Access layers: **Cloudflare Access** (email one-time PIN, your email only, 24 h session) →
  AOP client certificate + UFW (Cloudflare IPs only) → the app's own login (n8n owner account /
  OpenClaw gateway token + device pairing). n8n's webhook and form paths **bypass** Access.
- OpenClaw: LLM provider chosen in the wizard (guide is provider-neutral), **Telegram** via long
  polling, **Chromium installed but the browser tool off** (§10 turns it on). The agent is sandboxed
  **strictly**; §11* is an optional relaxed mode.
- n8n ↔ OpenClaw: three alternatives in §9 (no link / OpenClaw → n8n / both ways).
- Backups: encrypted with the **same age key** as the VPN server, copied to the **same rclone
  remote**, folder `apps-backups/`.
- Alerts: a small cron script sends Telegram messages through a **separate alert bot**.
- Versions are **pinned** and upgraded by hand. Debian security updates stay automatic.

Every command runs as **root** on the **new VPS**, unless a block says "on your local machine".
Replace `<ANGLE_BRACKETS>` with your own values. Version numbers are fetched live, not hardcoded.

| Placeholder | Meaning |
|---|---|
| `<NEW_VPS_IP>` | public IPv4 of this new server |
| `<OLD_VPS_IP>` | public IPv4 of the VPN+web server |
| `<yourdomain.com>` | your Cloudflare domain |
| `<Your/Timezone>` | e.g. `Europe/Berlin` (`timedatectl list-timezones` lists them) |

**Reading the expected-output comments** (same convention as the VPN guide):
- `# expected: ...` describes what a command should print. `# expected: no output` means success is silent.
- Commands not marked print nothing you need to check (apt progress, `chmod`, `mkdir`, …).
- Every `tee ... <<'EOF'` command echoes the file content back to the terminal. That's normal.
- Version numbers, keys, IDs, IPs and dates in the expected output are placeholders.

## 0. Order of operations

1. Prerequisites + baseline hardening (root password, SSH, UFW baseline, fail2ban, unattended upgrades, swap, journald cap)
2. Node.js 24 LTS
3. Reuse artifacts from the VPN server (certs, age key, rclone config)
4. Cloudflare (DNS, zone settings check, Cloudflare Access)
5. n8n (native, `127.0.0.1:5678`)
6. OpenClaw (native, `127.0.0.1:18789`) + Chromium (installed, off)
7. Nginx on 443 + finalize UFW (443 → Cloudflare only)
8. First login: n8n owner, OpenClaw Control UI, Telegram
9. n8n ↔ OpenClaw integration (pick one of three)
10. Optional: turn browser automation on/off
11. \* Optional: relaxed OpenClaw sandbox
12. Encrypted off-box backups
13. Telegram alerts
14. Final verification checklist
15. Maintenance, upgrades, rollback
16. Troubleshooting

**Memory budget** (2 GB box): system + Nginx + fail2ban ~250 MB, n8n ~300–450 MB (cap 800 MB),
OpenClaw gateway ~250–450 MB (cap 700 MB; 1.5 GB with the browser on). 2 GB swap as a buffer.
**Disk budget** (20 GB): OS ~2 GB, Node + n8n + OpenClaw + Chromium ~2.5–3 GB, data/logs/backups a few GB.

## 1. Prerequisites and baseline hardening

### 1.0 Prerequisites
```
apt update
apt install -y curl cron openssl ca-certificates jq age gnupg
systemctl enable --now cron
systemctl is-active cron
# expected: active
timedatectl set-timezone <Your/Timezone>
timedatectl show -p Timezone --value
# expected: <Your/Timezone>
hostnamectl set-hostname apps
```
The hostname appears in alert messages (§13) and in the shell prompt after the next login.

### 1.1 Strong root password
Replace the provider-issued password with a new one from your password manager (random, unique,
≥16 characters). Store it in the password manager first, then:
```
passwd
# expected: two "New password:" prompts (input is hidden), then:
#   passwd: password updated successfully
```
From a **new** terminal on your local machine, keeping the current session open:
```
ssh root@<NEW_VPS_IP>
# expected: a "root@<NEW_VPS_IP>'s password:" prompt; the new password gives a root shell
```
Don't continue until it works.

### 1.2 System update
```
apt update && apt full-upgrade -y
reboot
# expected: your SSH session drops; reconnect after ~30–60 s
```

### 1.3 SSH hardening (root with password, port 2222)
```
ls -l /etc/ssh/sshd_config.d/
# expected: "total 0" (empty) or provider files such as 50-cloud-init.conf
tee /etc/ssh/sshd_config.d/00-hardening.conf <<'EOF'
Port 2222
PermitRootLogin yes
PasswordAuthentication yes
PermitEmptyPasswords no
KbdInteractiveAuthentication no
MaxAuthTries 3
LoginGraceTime 30
EOF
sshd -t
# expected: no output
sshd -T | grep -Ei '^(port|passwordauthentication|permitrootlogin|permitemptypasswords|kbdinteractiveauthentication|maxauthtries|logingracetime) '
# expected (any order):
#   port 2222
#   permitrootlogin yes
#   passwordauthentication yes
#   permitemptypasswords no
#   kbdinteractiveauthentication no
#   maxauthtries 3
#   logingracetime 30
```
sshd uses the **first** value it reads, and `sshd_config.d/*.conf` is read in name order, so
`00-hardening.conf` wins. If a value differs, remove the conflicting line from the other file there.

```
systemctl is-active ssh.socket
# expected: inactive
systemctl restart ssh
ss -tlnp | grep sshd
# expected: LISTEN lines for 0.0.0.0:2222 and [::]:2222 (no :22)
```
If `ssh.socket` says **active**, use the socket override from VPN guide §1.3 instead.

From a **new** terminal (keep the old session open):
```
ssh -p 2222 root@<NEW_VPS_IP>
# expected: a password prompt, then a root shell
```
If your provider has its own network firewall, open 2222/tcp and 443/tcp there.

### 1.4 UFW baseline (443 → Cloudflare comes in §7.5)
```
apt install -y ufw
ufw default deny incoming
# expected: Default incoming policy changed to 'deny'
ufw default allow outgoing
# expected: Default outgoing policy changed to 'allow'
ufw allow 2222/tcp comment 'SSH'
# expected: Rules updated / Rules updated (v6)
ufw enable
# expected: a "Command may disrupt existing ssh connections" prompt; answer y, then:
#           Firewall is active and enabled on system startup
ufw status verbose
# expected:
#   Status: active
#   Default: deny (incoming), allow (outgoing), disabled (routed)
#   2222/tcp        ALLOW IN    Anywhere      # SSH
#   2222/tcp (v6)   ALLOW IN    Anywhere (v6) # SSH
```

### 1.5 fail2ban for SSH (journald backend)
```
apt install -y fail2ban python3-systemd
tee /etc/fail2ban/jail.local <<'EOF'
[sshd]
enabled  = true
port     = 2222
backend  = systemd
maxretry = 4
findtime = 10m
bantime  = 1h
EOF
systemctl enable fail2ban
systemctl restart fail2ban
systemctl is-active fail2ban
# expected: active
fail2ban-client status sshd
# expected: "Status for the jail: sshd", Currently failed: 0, Currently banned: 0
```
If you ban yourself, unban from the provider's web console: `fail2ban-client set sshd unbanip <YOUR_IP>` → expected: `1`.

### 1.6 Unattended security upgrades
```
apt install -y unattended-upgrades apt-listchanges
dpkg-reconfigure -plow unattended-upgrades
# expected: a dialog "Automatically download and install stable updates?" → choose Yes
cat /etc/apt/apt.conf.d/20auto-upgrades
# expected:
#   APT::Periodic::Update-Package-Lists "1";
#   APT::Periodic::Unattended-Upgrade "1";
```
This covers Debian security updates only. Node.js, n8n and OpenClaw are upgraded by hand (§15).

### 1.7 Swap (2 GB)
```
free -h | grep Swap
# expected: "Swap: 0B ..." on most new VPSs. If it already shows ~2Gi, skip to §1.8.
fallocate -l 2G /swapfile
chmod 600 /swapfile
mkswap /swapfile
# expected: Setting up swapspace version 1, size = 2 GiB (2147479552 bytes) ...
swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
echo 'vm.swappiness=10' > /etc/sysctl.d/99-swap.conf
sysctl -p /etc/sysctl.d/99-swap.conf
# expected: vm.swappiness = 10
free -h | grep Swap
# expected: Swap:  2.0Gi  0B  2.0Gi
```
If the provider already set up a smaller swap (e.g. 512 MB–1 GB), keep it and add this file on top.

### 1.8 Cap the journal
Both apps log to journald. Keep it from growing without limit:
```
mkdir -p /etc/systemd/journald.conf.d
tee /etc/systemd/journald.conf.d/size.conf <<'EOF'
[Journal]
SystemMaxUse=300M
EOF
systemctl restart systemd-journald
journalctl --disk-usage
# expected: Archived and active journals take up XX.XM in the file system.
```

## 2. Node.js 24 LTS

n8n supports Node 20.19–24.x; OpenClaw needs **Node ≥24.22.1** (or ≥26.12.1). Node 24 LTS satisfies
both. Debian's own `nodejs` package is too old, so use NodeSource's repository.

```
curl -fsSL https://deb.nodesource.com/setup_24.x -o /root/nodesource_setup.sh
bash /root/nodesource_setup.sh
# expected (end): a message that the NodeSource repository was added and "apt install nodejs" can be run
apt install -y nodejs
node --version
# expected: v24.22.1 or newer, but still v24.x
npm --version
# expected: 11.x.y (e.g. 11.19.1)
command -v node npm
# expected:
#   /usr/bin/node
#   /usr/bin/npm
npm config get prefix
# expected: /usr   (global packages go to /usr/lib/node_modules, commands to /usr/bin)
rm /root/nodesource_setup.sh
```
**Stay on npm 11.** npm 12 blocks dependency install scripts by default, which breaks n8n's
native modules (e.g. `sqlite3`). Never run `npm install -g npm@latest` on this box.

The NodeSource repo only serves the 24.x line, so `apt full-upgrade` brings Node 24 patch releases
but never jumps to a new major.

## 3. Reuse artifacts from the VPN server

You need four things that already exist on the VPN server:
- `/etc/nginx/ssl/origin.pem` + `origin.key` — the wildcard Cloudflare Origin certificate (VPN guide §3.3), valid for `*.<yourdomain.com>`
- `/etc/nginx/ssl/aop-ca.pem` — your AOP CA (VPN guide §3.5). Zone-level AOP applies to every proxied hostname in the zone, including the new ones.
- `/opt/backups/age-recipient.txt` — the age **public** key (VPN guide §7)
- `/root/.config/rclone/rclone.conf` — the rclone remote

Pull them in one SSH session (one password prompt for the **VPN server's** root password):
```
mkdir -p /root/from-vpn && chmod 700 /root/from-vpn
ssh -p 2222 root@<OLD_VPS_IP> 'tar czf - -C /etc/nginx/ssl origin.pem origin.key aop-ca.pem -C /opt/backups age-recipient.txt -C /root/.config/rclone rclone.conf' | tar xzf - -C /root/from-vpn
# expected: a "Are you sure you want to continue connecting" prompt the first time (answer yes),
#           then the VPN server's password prompt, then no output
ls -l /root/from-vpn
# expected: age-recipient.txt, aop-ca.pem, origin.key, origin.pem, rclone.conf
openssl x509 -in /root/from-vpn/origin.pem -noout -subject -ext subjectAltName
# expected:
#   subject=O=CloudFlare, Inc., OU=CloudFlare Origin CA, CN=CloudFlare Origin Certificate
#   X509v3 Subject Alternative Name:
#       DNS:*.<yourdomain.com>, DNS:<yourdomain.com>
```
These files are placed in §7 and §12.

If the VPN server has no `rclone.conf` yet (its backup step wasn't finished), drop
`-C /root/.config/rclone rclone.conf` from the command and run `rclone config` in §12.1 instead.

## 4. Cloudflare

All steps are in https://dash.cloudflare.com. The zone (domain) is already **Active** from the VPN guide.

### 4.1 DNS records
Select your domain → **DNS → Records → Add record**:

| Type | Name | IPv4 address | Proxy status | TTL |
|---|---|---|---|---|
| A | `n8n` | `<NEW_VPS_IP>` | **Proxied** (orange cloud) | Auto |
| A | `ctrl` | `<NEW_VPS_IP>` | **Proxied** (orange cloud) | Auto |

If the new VPS has public IPv6 (`ip -6 addr show scope global` prints an `inet6` line), add two
`AAAA` records the same way. Do **not** touch the website's `@`/`www` records.

Check from any machine:
```
dig +short n8n.<yourdomain.com>
dig +short ctrl.<yourdomain.com>
# expected: Cloudflare IPs (e.g. 104.21.x.x / 172.67.x.x), NOT <NEW_VPS_IP>
```

### 4.2 Zone settings (already set by the VPN guide — just check)
- **SSL/TLS → Overview**: **Full (strict)**. It's zone-wide, so it covers the new hostnames.
- **Rules → Overview**: the Origin Rule `website to 8443` must list **only** the website hostnames.
  `n8n.` and `ctrl.` must **not** be in it, because Nginx on the new VPS listens on 443.
- **SSL/TLS → Origin Server → Authenticated Origin Pulls**: **On** (zone-level, your own CA).
- **Security → Settings → Bot Fight Mode**: **Off** (it challenges webhook callers).
- **Speed → Optimization → Rocket Loader**: **Off** (it breaks the n8n editor and the Control UI).
- **Network → WebSockets**: **On**.

### 4.3 Cloudflare Access (Zero Trust)
Access puts an email one-time-PIN login in front of both hostnames at Cloudflare's edge, before
any request reaches the VPS.

**a) Enable Zero Trust (first time only).** Left sidebar → **Zero Trust**. Choose a team name (e.g.
`<yourname>`; your login page becomes `<team>.cloudflareaccess.com`) and the **Free** plan.
Cloudflare may ask for a payment method even on the free plan; nothing is charged for ≤50 users.

**b) One-time PIN login method.** **Zero Trust → Integrations → Identity providers → Add new
identity provider → One-time PIN** → **Save**.

**c) Reusable policy "only me".** **Zero Trust → Access controls → Policies → Add a policy**:
1. **Policy name**: `only me`. **Action**: **Allow**. **Session duration**: **24 hours**.
2. **Add include** → Selector **Emails** → Value `<your@email>`.
3. **Save**.

**d) Bypass policy for webhooks.** **Add a policy** again:
1. **Policy name**: `public bypass`. **Action**: **Bypass**.
2. **Add include** → Selector **Everyone**.
3. **Save**.

**e) Application: n8n.** **Zero Trust → Access controls → Applications → Create new application →
Self-hosted and private**:
1. **Application name**: `n8n`.
2. **Add public hostname**: Subdomain `n8n`, Domain `<yourdomain.com>`, Path empty.
3. **Access policies** → **Select existing policies** → `only me`.
4. **Login methods**: only **One-time PIN**; turn on **Apply instant authentication**.
5. **Session Duration**: **24 hours** → **Create**.

**f) Application: OpenClaw.** Same as (e) with name `openclaw` and subdomain `ctrl`.

**g) Application: n8n webhooks (bypass).** Create one more self-hosted application:
1. **Application name**: `n8n webhooks`.
2. Add **six public hostnames**, all Subdomain `n8n`, Domain `<yourdomain.com>`, with these paths:
   `webhook/*`, `webhook-test/*`, `webhook-waiting/*`, `form/*`, `form-test/*`, `form-waiting/*`.
3. **Access policies** → `public bypass` → **Create**.

The more specific application (with a path) wins over the bare hostname, so only those paths skip
the login. Webhooks are still protected by n8n itself: unknown paths return 404, and each Webhook
node should use **Header Auth** (§9.2).

Check from any machine (the origin isn't up yet, so the bypassed URL fails with a 5xx for now —
what matters is that it's *not* redirected):
```
curl -sI https://n8n.<yourdomain.com> | grep -iE '^(HTTP|location)'
# expected:
#   HTTP/2 302
#   location: https://<team>.cloudflareaccess.com/cdn-cgi/access/login/n8n.<yourdomain.com>?...
curl -sI https://ctrl.<yourdomain.com> | grep -iE '^(HTTP|location)'
# expected: HTTP/2 302 and a location: ...cloudflareaccess.com... line
curl -sI https://n8n.<yourdomain.com>/webhook/test | grep -iE '^(HTTP|location)'
# expected now: HTTP/2 52x (no location: line). After §7: HTTP/2 404
```
Some community reports say path bypasses occasionally stopped being honoured. §14 re-checks this.

## 5. n8n (native, `127.0.0.1:5678`)

### 5.1 Pick the version
```
npm view n8n dist-tags.stable
# expected: X.Y.Z (e.g. 2.44.6)
```
Pin exactly that version. Read `github.com/n8n-io/n8n/releases` before each upgrade.
n8n has announced that npm installs are deprecated **from n8n 3.0**; 2.x is fine (§15 covers what to do at 3.0).

### 5.2 System user and directories
```
useradd --system --home-dir /var/lib/n8n --create-home --shell /usr/sbin/nologin n8n
chmod 750 /var/lib/n8n
mkdir -p /etc/n8n
chmod 700 /etc/n8n
id n8n
# expected: uid=9xx(n8n) gid=9xx(n8n) groups=9xx(n8n)
```
n8n's data (SQLite DB, config, binary files) lives in `/var/lib/n8n/.n8n`.

### 5.3 Install
```
npm install -g n8n@<X.Y.Z>
# expected: takes 3–10 minutes; may print "npm warn deprecated ..." lines (harmless), ends with
#   added NNNN packages in Xm
npm ls -g --depth=0 n8n
# expected:
#   /usr/lib
#   └── n8n@<X.Y.Z>
# expected: npm warn using --force Recommended protections disabled.
du -sh /usr/lib/node_modules/n8n
# expected: roughly 600M–1.2G
```
Don't run `n8n` or `openclaw` commands directly as root: they'd create state in `/root`. Use the
`n8nc` / `oc` helpers (§5.6, §6.3), which run them as the service user.
npm can use ~1 GB RAM during the install; swap (§1.7) covers that. If the install fails with
`gyp ERR!` or `node-pre-gyp` errors, see §16.

### 5.4 Environment file
```
openssl rand -hex 32
# expected: 64 hex chars → <N8N_ENCRYPTION_KEY>; save it in the password manager NOW
tee /etc/n8n/n8n.env <<'EOF'
# --- URLs (public side is Cloudflare -> Nginx -> 127.0.0.1:5678) ---
N8N_HOST=n8n.<yourdomain.com>
N8N_PROTOCOL=https
N8N_PORT=5678
N8N_LISTEN_ADDRESS=127.0.0.1
WEBHOOK_URL=https://n8n.<yourdomain.com>/
N8N_EDITOR_BASE_URL=https://n8n.<yourdomain.com>/
N8N_PROXY_HOPS=1

# --- Secrets ---
N8N_ENCRYPTION_KEY=<N8N_ENCRYPTION_KEY>

# --- Storage: SQLite + files on disk (not RAM) ---
DB_TYPE=sqlite
DB_SQLITE_VACUUM_ON_STARTUP=true
N8N_DEFAULT_BINARY_DATA_MODE=filesystem
EXECUTIONS_DATA_PRUNE=true
EXECUTIONS_DATA_MAX_AGE=168
EXECUTIONS_DATA_PRUNE_MAX_COUNT=5000

# --- Housekeeping ---
N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS=true
N8N_DIAGNOSTICS_ENABLED=false
N8N_PERSONALIZATION_ENABLED=false
GENERIC_TIMEZONE=<Your/Timezone>
TZ=<Your/Timezone>
NODE_ENV=production
NODE_OPTIONS=--max-old-space-size=512
EOF
chmod 600 /etc/n8n/n8n.env
```
- `N8N_ENCRYPTION_KEY` encrypts every credential stored in n8n. **If it's lost, backups can't
  decrypt any credential.** Never change it after the first start.
- `N8N_LISTEN_ADDRESS=127.0.0.1`: only Nginx (on this host) can reach n8n.
- `EXECUTIONS_DATA_*`: keep 7 days / at most 5000 executions, so SQLite stays small.
  `DB_SQLITE_VACUUM_ON_STARTUP` reclaims the freed space on each restart.
- `NODE_OPTIONS=--max-old-space-size=512`: caps the JavaScript heap below the systemd cap.

### 5.5 systemd service (sandboxed, memory-capped)
```
tee /etc/systemd/system/n8n.service <<'EOF'
[Unit]
Description=n8n workflow automation
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=n8n
Group=n8n
Environment=HOME=/var/lib/n8n
EnvironmentFile=/etc/n8n/n8n.env
WorkingDirectory=/var/lib/n8n
ExecStart=/usr/bin/n8n start
Restart=on-failure
RestartSec=10

# Memory: soft limit (reclaim/swap) and hard limit (OOM-kill only this service)
MemoryHigh=650M
MemoryMax=800M

# Sandbox
NoNewPrivileges=yes
ProtectSystem=strict
ReadWritePaths=/var/lib/n8n
ProtectHome=yes
PrivateTmp=yes
PrivateDevices=yes
ProtectKernelTunables=yes
ProtectKernelModules=yes
ProtectKernelLogs=yes
ProtectControlGroups=yes
ProtectClock=yes
ProtectHostname=yes
RestrictSUIDSGID=yes
RestrictRealtime=yes
LockPersonality=yes
RestrictAddressFamilies=AF_INET AF_INET6 AF_UNIX AF_NETLINK
UMask=0077

[Install]
WantedBy=multi-user.target
EOF
systemctl daemon-reload
systemctl enable --now n8n
systemctl is-active n8n
# expected: active
journalctl -u n8n -n 30 --no-pager
# expected (after ~20–60 s on first start, which runs DB migrations):
#   ... Editor is now accessible via:
#   ... https://n8n.<yourdomain.com>
```
- `ProtectSystem=strict` + `ReadWritePaths`: the whole filesystem is read-only for n8n except
  `/var/lib/n8n`. `ProtectHome=yes` hides `/root` and `/home`.
- There's deliberately no `MemoryDenyWriteExecute`: Node's JIT needs writable+executable memory.

Verify:
```
curl -s http://127.0.0.1:5678/healthz; echo
# expected: {"status":"ok"}
ss -tlnp | grep 5678
# expected: one LISTEN line on 127.0.0.1:5678 users:(("node",...)). NOT 0.0.0.0 or [::]
systemctl show n8n -p MemoryCurrent -p MemoryMax
# expected: MemoryCurrent=2xxxxxxxx (≈200–450 MB) / MemoryMax=838860800
ls -la /var/lib/n8n/.n8n/
# expected: config, database.sqlite, binaryData/ ... owned by n8n
```
Don't open the UI yet. The owner account is created in §8.1, after Nginx is in front.

### 5.6 Helper for n8n CLI commands
For maintenance commands (user reset, exports), run the CLI as `n8n` with the same environment:
```
tee -a /root/.bashrc <<'EOF'
n8nc() { ( set -a; . /etc/n8n/n8n.env; set +a; cd /var/lib/n8n && runuser -u n8n -- env HOME=/var/lib/n8n n8n "$@" ); }
EOF
source /root/.bashrc
n8nc --version
# expected: <X.Y.Z>
```

## 6. OpenClaw (native, `127.0.0.1:18789`)

### 6.1 Pick the version
```
npm view openclaw dist-tags --json
# expected: { "latest": "YYYY.M.D", "extended-stable": "YYYY.M.D", "beta": "..." }
npm view openclaw@<YYYY.M.D> engines.node
# expected: >=24.22.1 <25 || >=26.12.1   (your `node --version` from §2 must satisfy it)
```
Pin the exact `latest` version. Check `github.com/openclaw/openclaw/releases` and
`github.com/openclaw/openclaw/security/advisories` weekly (§15).

### 6.2 System user and install
```
useradd --system --home-dir /var/lib/openclaw --create-home --shell /usr/sbin/nologin openclaw
chmod 750 /var/lib/openclaw
npm install -g openclaw@<YYYY.M.D> --allow-scripts=openclaw
# expected: takes 2–6 minutes; ends with "added NNN packages in Xm"
#   (a postinstall step for bundled plugins runs; "npm warn" lines are harmless)
npm ls -g --depth=0 openclaw
# expected:
#   /usr/lib
#   └── openclaw@<YYYY.M.D>
command -v openclaw
# expected: /usr/bin/openclaw
npm cache clean --force
```
`--allow-scripts=openclaw` lets OpenClaw's own postinstall run on npm ≥11.16 without warnings.

### 6.3 Helper for OpenClaw CLI commands

### 6.7 Keep the two apps from talking over loopback
Both apps listen on `127.0.0.1`, so by default each *could* connect to the other's port. Block
that with UFW owner rules (the kernel knows which user opened each connection). §9 opens exactly
what an integration needs.
```
cp /etc/ufw/before.rules /etc/ufw/before.rules.bak
cp /etc/ufw/before6.rules /etc/ufw/before6.rules.bak
for f in /etc/ufw/before.rules /etc/ufw/before6.rules; do
  sed -i '/^-A ufw6\?-before-output -o lo -j ACCEPT/i \
-A ufw-before-output -o lo -p tcp --dport 5678 -m owner --uid-owner openclaw -j REJECT --reject-with tcp-reset -m comment --comment "openclaw-to-n8n"\
-A ufw-before-output -o lo -p tcp --dport 18789 -m owner --uid-owner n8n -j REJECT --reject-with tcp-reset -m comment --comment "n8n-to-openclaw"' "$f"
done
sed -i 's/^-A ufw-before-output -o lo -p tcp/-A ufw6-before-output -o lo -p tcp/' /etc/ufw/before6.rules
grep -c 'openclaw-to-n8n\|n8n-to-openclaw' /etc/ufw/before.rules /etc/ufw/before6.rules
# expected:
#   /etc/ufw/before.rules:2
#   /etc/ufw/before6.rules:2
ufw reload
# expected: Firewall reloaded
iptables -S ufw-before-output | head -4
# expected: the two REJECT rules (with --uid-owner) appear BEFORE "-o lo -j ACCEPT"
```
Test:
```
runuser -u openclaw -- curl -s -m 5 -o /dev/null -w '%{http_code}\n' http://127.0.0.1:5678/healthz
# expected: 000   (connection reset — OpenClaw can't reach n8n)
runuser -u n8n -- curl -s -m 5 -o /dev/null -w '%{http_code}\n' http://127.0.0.1:18789/healthz
# expected: 000   (n8n can't reach OpenClaw)
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:5678/healthz
# expected: 200   (root and Nginx still can)
```
If `ufw reload` reports an error, restore the backups (`cp /etc/ufw/before.rules.bak /etc/ufw/before.rules`, same for `before6`) and re-check the `sed` step.

### 7.3 Sites
WebSocket helper (both apps use WebSockets):

n8n:
```
tee /etc/nginx/sites-available/n8n.conf <<'EOF'

    client_max_body_size 50m;

    location / {
        proxy_pass http://127.0.0.1:5678;

        proxy_set_header Upgrade           $http_upgrade;
        proxy_set_header Connection        $connection_upgrade;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $http_cf_connecting_ip;
        proxy_set_header X-Forwarded-For   $http_cf_connecting_ip;
        proxy_set_header X-Forwarded-Proto https;
        proxy_set_header X-Forwarded-Host  $host;
        proxy_buffering off;
        proxy_read_timeout 300s;
    }
}
EOF
```
OpenClaw:
```
tee /etc/nginx/sites-available/openclaw.conf <<'EOF'
server {
    listen 443 ssl;
    listen [::]:443 ssl;
    http2 on;
    server_name ctrl.<yourdomain.com>;

    ssl_certificate     /etc/nginx/ssl/origin.pem;
    ssl_certificate_key /etc/nginx/ssl/origin.key;
    ssl_client_certificate /etc/nginx/ssl/aop-ca.pem;
    ssl_verify_client on;

    # Inbound agent hooks (§9.3) are for local callers only, never via the public hostname.
    location /hooks { return 404; }

    location / {
        proxy_pass http://127.0.0.1:18789;
        proxy_http_version 1.1;
        proxy_set_header Upgrade           $http_upgrade;
        proxy_set_header Connection        $connection_upgrade;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $http_cf_connecting_ip;
        proxy_set_header X-Forwarded-For   $http_cf_connecting_ip;
        proxy_set_header X-Forwarded-Proto https;
        proxy_set_header X-Forwarded-Host  $host;
        proxy_read_timeout 3600s;
        proxy_send_timeout 3600s;
    }
}
EOF
```
- No basic auth: Cloudflare Access does that job at the edge.
- `X-Forwarded-For $http_cf_connecting_ip` **overwrites** whatever the client sent with the real
  visitor IP from Cloudflare. AOP guarantees only Cloudflare reaches this server, so the header is trustworthy.
- `proxy_buffering off` (n8n) streams execution updates without delay. Long timeouts (OpenClaw)
  keep the Control UI's WebSocket open while idle.
- Webhooks that run longer than ~100 s hit Cloudflare's timeout (error 524); use
  "Respond: Immediately" in the Webhook node for long workflows.

### 7.5 UFW: 443 → Cloudflare only
Same script as the VPN guide §5, for port 443:

```
set -euo pipefail

#   [ 2] 443/tcp                    ALLOW IN    173.245.48.0/20   # Cloudflare
#   ... one 443 line per Cloudflare CIDR, then the (v6) equivalents

(crontab -l 2>/dev/null; echo "0 4 1 * * /usr/local/sbin/cf-ufw-refresh.sh") | crontab -
```

## 9. n8n ↔ OpenClaw integration (pick one)

| Variant | OpenClaw → n8n | n8n → OpenClaw | What each side holds |
|---|---|---|---|
| **9.1 No link** | blocked | blocked | nothing |
| **9.2 OpenClaw → n8n** | n8n webhook over HTTPS (public URL) | blocked | OpenClaw: one webhook secret |
| **9.3 Both ways** | as 9.2 | OpenClaw hook on `127.0.0.1` | n8n: a hook token (**not** the gateway token) |

In all variants OpenClaw never gets n8n credentials or API access, and the loopback block from §6.7
stays for OpenClaw → n8n. You can move between variants at any time.

### 9.1 No link
Nothing to do: §6.7 already blocks both directions. Verify:
```
grep -c 'openclaw-to-n8n\|n8n-to-openclaw' /etc/ufw/before.rules
# expected: 2

# expected: false (or "not set")
```

### 9.2 OpenClaw → n8n (webhook)
OpenClaw calls a normal n8n webhook through the **public** URL (Cloudflare → bypass → Nginx → n8n),
protected by a header secret. It never touches n8n's loopback port.

1. Create the secret and give it to the `openclaw` user only:
   ```
   openssl rand -hex 32 | tee /var/lib/openclaw/.n8n-webhook-token >/dev/null
   chown openclaw:openclaw /var/lib/openclaw/.n8n-webhook-token
   chmod 600 /var/lib/openclaw/.n8n-webhook-token
   cat /var/lib/openclaw/.n8n-webhook-token
   # expected: 64 hex chars (you'll paste this into n8n once)
   ```
2. In n8n: **Create workflow** → add **Webhook** node:
   - **HTTP Method**: POST. **Path**: `openclaw-inbox`.
   - **Authentication**: **Header Auth** → **Create new credential** → **Name** `X-Webhook-Token`,
     **Value** = the 64 hex chars → **Save**.
   - **Respond**: Immediately.
   - Add whatever should happen next (e.g. a **Set** or **Telegram** node). **Save** and
     **Publish/Activate** the workflow (toggle at the top right).
3. Test as the `openclaw` user:
   ```
   runuser -u openclaw -- sh -c 'curl -s -X POST https://n8n.<yourdomain.com>/webhook/openclaw-inbox \
     -H "X-Webhook-Token: $(cat /var/lib/openclaw/.n8n-webhook-token)" \
     -H "Content-Type: application/json" -d "{\"text\":\"hello from openclaw\"}"'; echo
   # expected: {"message":"Workflow was started"}
   curl -s -X POST https://n8n.<yourdomain.com>/webhook/openclaw-inbox -d '{}'; echo
   # expected: Authorization data is wrong!   (without the header it's refused)
   ```
   n8n's **Executions** tab shows one successful run.
4. Tell the agent how to use it. Append to its workspace notes:
   ```
   runuser -u openclaw -- mkdir -p /var/lib/openclaw/.openclaw/workspace
   runuser -u openclaw -- tee -a /var/lib/openclaw/.openclaw/workspace/TOOLS.md <<'EOF'

   ## n8n inbox
   To hand a task or data to n8n, POST JSON to https://n8n.<yourdomain.com>/webhook/openclaw-inbox
   with header "X-Webhook-Token: <contents of ~/.n8n-webhook-token>" and "Content-Type: application/json".
   Never print or send the token anywhere else.
   EOF
   ```
   Expected: the text is echoed back. Ask the bot in Telegram to "send a test message to the n8n
   inbox"; a new execution appears in n8n.

To add more endpoints, repeat step 2 with another path (same credential) and document it in `TOOLS.md`.

### 9.3 Both ways (adds n8n → OpenClaw)

requires it to differ from the gateway token) and let only the `n8n` user reach port 18789.

## 11. \* Optional: relaxed OpenClaw sandbox

**Only if you decide the agent must install packages itself.** This effectively gives the agent
root: `apt-get install` can run arbitrary package scripts as root. Anyone who can talk to the agent
(you, an approved Telegram sender, anything n8n forwards in §9.3) could then take over the server,
including n8n's credentials. Prefer installing tools yourself as root.

### 11.1 Turn on
```
apt install -y sudo
tee /etc/sudoers.d/openclaw <<'EOF'
openclaw ALL=(root) NOPASSWD: /usr/bin/apt-get update, /usr/bin/apt-get install *, /usr/bin/systemctl status *
EOF
chmod 440 /etc/sudoers.d/openclaw
visudo -c
# expected: /etc/sudoers: parsed OK  /etc/sudoers.d/openclaw: parsed OK
mkdir -p /etc/systemd/system/openclaw.service.d
tee /etc/systemd/system/openclaw.service.d/relaxed.conf <<'EOF'
[Service]
NoNewPrivileges=no
RestrictSUIDSGID=no
ProtectSystem=no
PrivateDevices=no
EOF
systemctl daemon-reload
systemctl restart openclaw
runuser -u openclaw -- sudo -n /usr/bin/apt-get update >/dev/null && echo OK
# expected: OK
```
`ProtectHome=yes` stays, so `/root` remains hidden; `/var/lib/n8n` stays unreadable (mode 750).

### 11.2 Turn off
```
rm /etc/sudoers.d/openclaw /etc/systemd/system/openclaw.service.d/relaxed.conf
systemctl daemon-reload
systemctl restart openclaw
runuser -u openclaw -- sudo -n true
# expected: "sudo: a password is required" or "not allowed" — i.e. no sudo
```

### 12.2 Backup script
Both apps keep SQLite files that can be corrupted if copied mid-write, so the script stops them
for a few seconds and always starts them again.
```
tee /opt/backups/backup.sh <<'EOF'
#!/usr/bin/env bash
set -euo pipefail
umask 077
STAMP=$(date +%F)
WORK=$(mktemp -d -p /var/tmp)

start_apps() { systemctl start n8n openclaw || true; }
trap 'start_apps; rm -rf "$WORK"' EXIT

# System config
mkdir -p "$WORK/etc"
cp -r /etc/nginx /etc/n8n /etc/ssh/sshd_config.d /etc/fail2ban/jail.local \
      /etc/ufw/before.rules /etc/ufw/before6.rules "$WORK/etc/"
cp /etc/systemd/system/n8n.service /etc/systemd/system/openclaw.service "$WORK/etc/"
[ -d /etc/systemd/system/openclaw.service.d ] && cp -r /etc/systemd/system/openclaw.service.d "$WORK/etc/"
[ -f /etc/vps-alert.env ] && cp /etc/vps-alert.env "$WORK/etc/"
cp /usr/local/sbin/*.sh "$WORK/etc/" 2>/dev/null || true
crontab -l > "$WORK/etc/root.crontab"
{ npm ls -g --depth=0 n8n openclaw; echo "node $(node --version)"; } > "$WORK/versions.txt"

# App data: stop briefly for a consistent copy
systemctl stop n8n openclaw
tar czf "$WORK/n8n.tar.gz" -C /var/lib n8n
tar czf "$WORK/openclaw.tar.gz" -C /var/lib --exclude='openclaw/.cache' openclaw
start_apps

tar czf - -C "$WORK" . | age -R /opt/backups/age-recipient.txt \
  -o "/opt/backups/apps-backup-$STAMP.tar.gz.age"

find /opt/backups -name 'apps-backup-*.tar.gz.age' -mtime +7 -delete
EOF
chmod 700 /opt/backups/backup.sh
/opt/backups/backup.sh
# expected: no output (~10–30 s; both apps are stopped for part of it)
ls -lh /opt/backups/
# expected: age-recipient.txt, backup.sh, apps-backup-YYYY-MM-DD.tar.gz.age (a few MB)
head -c 21 /opt/backups/apps-backup-$(date +%F).tar.gz.age; echo
# expected: age-encryption.org/v1
systemctl is-active n8n openclaw
# expected:
#   active
#   active
```
`/var/tmp` is used for the work directory because `/tmp` is in RAM on Debian 13.

### 12.3 Schedule + off-box copy

```
(crontab -l 2>/dev/null; echo "0 3 * * * /opt/backups/backup.sh") | crontab -
(crontab -l 2>/dev/null; echo "30 3 * * * rclone copy /opt/backups/ remote:apps-backups/ --include 'apps-backup-*.tar.gz.age'") | crontab -
crontab -l
# expected: three lines – cf-ufw-refresh.sh (0 4 1 * *), backup.sh (0 3 * * *), rclone copy (30 3 * * *)
rclone copy /opt/backups/ remote:apps-backups/ --include 'apps-backup-*.tar.gz.age'
rclone ls remote:apps-backups/
# expected: <size> apps-backup-YYYY-MM-DD.tar.gz.age
```

## 13. Telegram alerts

A **separate** bot, so alerts still arrive when OpenClaw is broken. The script runs every 5 minutes
from cron, uses no RAM between runs, and only messages on **change** (problem appears / clears).

### 13.1 Alert bot
1. `@BotFather` → `/newbot` → e.g. `apps-alerts` / `<something>_alerts_bot` → copy the token.
2. Send that bot any message from your account, then get your chat ID:
   ```
   curl -s "https://api.telegram.org/bot<ALERT_BOT_TOKEN>/getUpdates" | jq '.result[-1].message.chat.id'
   # expected: your numeric chat ID, e.g. 123456789   (null = you haven't messaged the bot yet)
   tee /etc/vps-alert.env <<'EOF'
   TG_TOKEN=<ALERT_BOT_TOKEN>
   TG_CHAT=<CHAT_ID>
   EOF
   chmod 600 /etc/vps-alert.env
   ```

### 13.2 Script
```
tee /usr/local/sbin/vps-alert.sh <<'EOF'
#!/usr/bin/env bash
set -uo pipefail
. /etc/vps-alert.env
STATE=/var/lib/vps-alert/last
mkdir -p /var/lib/vps-alert

send() {
  curl -fsS -m 15 "https://api.telegram.org/bot${TG_TOKEN}/sendMessage" \
    --data-urlencode "chat_id=${TG_CHAT}" --data-urlencode "text=[$(hostname)] $1" >/dev/null
}
[ "${1:-}" = "--test" ] && { send "test alert"; exit; }

problems=()
for s in nginx n8n openclaw fail2ban ssh cron; do
  systemctl is-active --quiet "$s" || problems+=("$s is $(systemctl is-active "$s")")
done
disk=$(df --output=pcent / | tail -1 | tr -dc 0-9)
[ "$disk" -ge 85 ] && problems+=("disk ${disk}% full")
avail=$(awk '/MemAvailable/{a=$2}/MemTotal/{t=$2}END{print int(a*100/t)}' /proc/meminfo)
[ "$avail" -lt 10 ] && problems+=("RAM available ${avail}%")
journalctl -k --since "-10 min" -q 2>/dev/null | grep -qi 'out of memory' && problems+=("OOM kill in the last 10 min")
latest=$(ls -t /opt/backups/apps-backup-*.tar.gz.age 2>/dev/null | head -1)
if [ -z "$latest" ] || [ $(( $(date +%s) - $(stat -c %Y "$latest") )) -gt 93600 ]; then
  problems+=("no backup in the last 26 h")
fi

msg=$(printf '%s\n' "${problems[@]}")
last=$(cat "$STATE" 2>/dev/null || true)
if [ "$msg" != "$last" ]; then
  if [ -n "$msg" ]; then send "PROBLEM:
$msg"; else send "RECOVERED: all checks OK"; fi
  printf '%s' "$msg" > "$STATE"
fi
EOF
chmod 700 /usr/local/sbin/vps-alert.sh
/usr/local/sbin/vps-alert.sh --test
# expected: no output; Telegram shows "[apps] test alert"
/usr/local/sbin/vps-alert.sh
# expected: no output (all OK, nothing changed)
(crontab -l 2>/dev/null; echo "*/5 * * * * /usr/local/sbin/vps-alert.sh") | crontab -
crontab -l | tail -1
# expected: */5 * * * * /usr/local/sbin/vps-alert.sh
```
Test a real alert:
```
systemctl stop nginx; /usr/local/sbin/vps-alert.sh
# expected: Telegram "[apps] PROBLEM: nginx is inactive"
systemctl start nginx; /usr/local/sbin/vps-alert.sh
# expected: Telegram "[apps] RECOVERED: all checks OK"
```

## 15. Maintenance, upgrades, rollback

### 15.1 Cadence
- **Weekly:** OpenClaw releases/advisories vs `openclaw --version`; upgrade immediately on a critical advisory (§15.3).
- **Monthly:** `apt update && apt full-upgrade -y` (also brings Node 24 patch releases; reboot if the
  kernel changed); n8n upgrade (§15.2); `ufw status | grep -c Cloudflare` matches the CIDR count;
  `df -h /` and `journalctl --disk-usage` look sane; `oc devices list` contains only your devices.
- **Quarterly:** full restore test (§12.4); rotate the gateway token (`oc config set gateway.auth.token <new>`,
  restart, re-enter it in the UI) and the hook token if used.
- **Before ~2 years:** the AOP client certificate expires; renewing it on the VPN server (VPN guide §9)
  covers this server too, since AOP is zone-wide. If you also rotate the AOP **CA**, copy the new
  `aop-ca.pem` here and `systemctl reload nginx`.
- **Never** change `N8N_ENCRYPTION_KEY`.

### 15.2 Upgrade n8n
```
npm view n8n dist-tags.stable
# expected: <NEW_X.Y.Z>   (read the release notes first, especially for a new minor/major)
/opt/backups/backup.sh                # DB migrations can't be undone; this is your rollback point
npm install -g n8n@<NEW_X.Y.Z>
# expected: "changed NNN packages in Xm"
systemctl restart n8n
journalctl -u n8n -n 30 --no-pager
# expected: migration lines (if any), then "Editor is now accessible via:"
n8nc --version
# expected: <NEW_X.Y.Z>
npm cache clean --force
```
**Rollback:** `systemctl stop n8n`, restore `/var/lib/n8n` from the backup taken above (extract
`n8n.tar.gz` into `/var/lib`, `chown -R n8n:n8n /var/lib/n8n`), `npm install -g n8n@<OLD_X.Y.Z>`,
`systemctl start n8n`. Installing the old version **without** restoring the DB fails if migrations ran.

**n8n 3.0:** npm installs are deprecated from 3.0. Stay on the 2.x line until you decide; the
`dist-tags` command will show 3.x as `stable`. Then either follow n8n's 3.0 hosting docs or run
only n8n in Docker (bound to `127.0.0.1:5678`, data in `/var/lib/n8n`) — Nginx and Access don't change.

### 15.3 Upgrade OpenClaw
```
npm view openclaw dist-tags --json
npm view openclaw@<NEW_YYYY.M.D> engines.node
# expected: a range your `node --version` satisfies (otherwise upgrade Node first)
/opt/backups/backup.sh
npm install -g openclaw@<NEW_YYYY.M.D> --allow-scripts=openclaw
# expected: "changed NNN packages in Xm"
oc doctor
# expected: checks pass; if the release notes call for it: oc doctor --fix
systemctl restart openclaw
oc --version
# expected: <NEW_YYYY.M.D>
oc health
# expected: healthy/OK
npm cache clean --force
```
**Rollback:** `npm install -g openclaw@<OLD_YYYY.M.D> --allow-scripts=openclaw`, restore
`/var/lib/openclaw` from the backup if the new version migrated its config, `systemctl restart openclaw`.

### 15.4 Switch LLM provider
```
oc onboard --mode local --no-install-daemon
# re-run the wizard: change only the model/provider step, keep gateway settings as they are
systemctl restart openclaw
```
Or use the Control UI's settings. Revoke the old API key at the old provider afterwards.

## 16. Troubleshooting

| Symptom | Likely cause | Check / fix |
|---|---|---|
| 302 to `cloudflareaccess.com` on `/webhook/...` | Bypass app missing or path mismatch | §4.3 g: six paths with `/*`; a path app must exist for each prefix |
| Access login loops / "invalid email" | Email not in `only me`, or wrong login method | §4.3 c, e |
| 521 / 522 | Nginx down, or UFW blocks Cloudflare, or hostname is in the old Origin Rule (→ port 8443) | `systemctl status nginx`, §7.5, §4.2 |
| 525 / 526 | Wrong/mismatched origin cert or key | §7.2 modulus check |
| 400 "No required SSL certificate was sent" | Zone-level AOP off, or wrong `aop-ca.pem` | VPN guide §3.5; §7.2 subject check |
| 502 Bad Gateway (nginx page) | App not running | `systemctl status n8n` / `openclaw`; `journalctl -u <app> -n 50` |
| `npm install` fails with `gyp ERR!` / `node-pre-gyp` | Native module had to be compiled | `apt install -y build-essential python3`, retry; check `npm --version` is 11.x (§2) |
| n8n crash loop, log says `heap out of memory` | Heap cap too small for a workflow | Raise `--max-old-space-size` (e.g. 640) and `MemoryMax` (e.g. 900M) together; restart |
| `dmesg` / journal shows "Memory cgroup out of memory" for one app | Its systemd cap was hit | Same as above, or reduce workload; check `free -h` first |
| n8n "Connection lost" banner | WebSocket upgrade not passed | `/etc/nginx/conf.d/websocket-map.conf` present, `nginx -t`; Cloudflare WebSockets On |
| n8n shows `http://` or `localhost` URLs | Wrong `WEBHOOK_URL` / `N8N_HOST` | `/etc/n8n/n8n.env`, `systemctl restart n8n` |
| Forgot n8n owner password | — | `n8nc user-management:reset`, `systemctl restart n8n`, then set up the owner again (workflows stay) |
| Control UI: origin not allowed | `allowedOrigins` mismatch | §6.5; must be exactly `https://ctrl.<yourdomain.com>` |
| Control UI: unauthorized / 1008 | Wrong gateway token | `oc gateway auth-token --show` |
| Control UI: pairing required, stuck | Device not approved | `oc devices list` → `oc devices approve <requestId>` |
| `oc ...` fails: permission denied on a file | File created as root | `chown -R openclaw:openclaw /var/lib/openclaw` |
| Browser tool: `No usable sandbox` / namespace errors | Chromium's own sandbox can't start inside systemd's | `sysctl kernel.unprivileged_userns_clone` should be 1; else `oc config set browser.noSandbox true --strict-json` and restart (the systemd sandbox still applies) |
| Browser tool: "Browser disabled" | One of the two switches is off | §10.1: both `browser.enabled` and `plugins.entries.browser.enabled` must be `true` |
| `ufw reload` error after §6.7 / §9 | Broken `before*.rules` edit | Restore `.bak` files, `ufw reload`, redo the step |
| Alerts never arrive | Token/chat ID wrong, or cron line missing | `vps-alert.sh --test`; `crontab -l` |
| 524 on a webhook | Workflow ran > ~100 s before responding | Webhook node → Respond: Immediately |
